What This Is

THE DESIGN SYSTEM

Dark Editorial is the base visual language for Storyteller content. Every article, every document, every public-facing page starts here.

The premise is simple: make reading feel like an event. Not a wall of text, but a world you enter. Dark background, deliberate typography, color that means something. Each section gets its own accent — violet, blue, emerald, amber, crimson — so you always know where you are without reading a heading.

This is a design system, not a template. The same structural rules apply to short articles, long technical docs, and marketing pages. The content changes; the grammar stays the same.

02
The System

HOW IT'S BUILT

One HTML file. All CSS inline. All JS inline. No frameworks, no build step, no dependencies except Google Fonts.

The constraint is intentional. A design that requires a build pipeline is a design that requires maintenance. These files should work in ten years on a plain static host.

Every animation respects prefers-reduced-motion. Every color shift is driven by CSS custom properties updated in real time as you scroll. The accent color you see in the nav, the cursor glow, the progress bar — all one JavaScript variable, changing live.

The story never breaks to explain itself. Neither does the design.

Design Principle
  • IntersectionObserver — every element reveals itself on scroll. Threshold 0.15, rootMargin compensates for nav height.
  • requestAnimationFrame — parallax, cursor tracking, and scroll velocity all go through rAF to stay at 60fps.
  • CSS custom properties — --active-accent, --active-accent-rgb, and three tint channels update live on section change.
  • Section observer — detects which section is in viewport at 30% threshold, updates nav highlight and accent color.
  • Hero load sequence — staggered setTimeout chain: nav 200ms, eyebrow 300ms, title words 400–700ms, rule 750ms, subtitle 800ms.
  • Typewriter on scroll — pull quotes type out character by character when they enter the viewport, restore HTML on completion.

Storyteller — System Overview
AN AI THAT RUNS
THE GAME FOR YOU
The Narrator remembers every detail, adjusts on the fly, and never breaks the spell. This is how it works.

When you start a session, a voice called the Narrator takes over. It describes the world, plays the characters, and reacts to whatever you say. Hesitate, and it notices. Be rude to someone in the story, and they remember.

Several pieces run quietly behind the Narrator. The Guide handles onboarding and anything outside the fiction. The Deejay manages music and sound in real time. The Chronicle remembers everything across every session. The Play Engine runs all of them, second by second.

Stories are packaged as .tome files — StoryPaks — that run on the Play Engine the way an app runs on a phone. One engine, many stories. Stories can't touch each other.
